# Phase 12：テスト・エラー処理・権限・仕上げ

## 実装した内容

### 二重登録防止と再試行

- 会計確定は、入力内容が変わらない限り同じ `idempotency key` を使って再送します。
- 手動請求の作成も同じ方式です。
- Supabase側の `checkout_sale_with_invoice()` と `create_manual_invoice()` は、組織・操作種別・キーの一意制約を利用します。同じ要求を再送しても、売上や請求を二重登録しません。
- 会計・請求・取消の実行中は該当ボタンを無効化します。
- 通信失敗時に自動で再送はしません。金銭を扱う処理のため、入力内容を画面に保持した状態で、担当者が通信回復後に同じ操作を再試行する方式です。

### 通信・権限エラー

- 全画面共通のオフライン通知を追加しました。
- 顧客・車両・商品マスタを含む全画面で、次のメッセージを区別して表示します。
  - ネットワーク切断：通信復旧後の再試行を案内
  - 権限不足：管理者への問い合わせを案内
  - ログイン期限切れ：再読み込み・再ログインを案内
  - Supabase RPCの業務エラー：内容をそのまま表示
- Reactの描画例外を捕捉するエラーバウンダリを追加しました。予期しない画面エラー時は、再読み込みの導線を表示します。

### 権限の最終確認

- 画面上の操作制御に加え、売上確定・請求作成・請求状態変更・取消はSupabase RPC内でもログイン利用者・組織・ロールを検証します。
- `staff` は単価変更、商品マスタ編集、売上取消、請求状態変更、発行元設定保存を実行できません。
- `admin` は上記の管理操作を実行できます。サーバー側のRLS/RPC検証が最終的な権限制御です。

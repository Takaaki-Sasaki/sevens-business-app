# Phase 8：売上から請求への連携

## 実装した内容

- 確定済み売上から請求ヘッダ・請求明細を自動作成
  - 顧客、商品名、数量、単価、割引、小計、税額、合計を販売時点のスナップショットから複写
  - `invoices.source_sale_id` により、元の売上と関連付け
- レジでの請求作成
  - **掛売**：会計確定と同じトランザクションで請求データを自動作成
  - **現金・カード等**：管理者は「この会計から請求データも作成する」を任意選択可能
- 売上履歴での請求作成
  - 管理者は、件名・請求月・支払期限を指定して請求データを作成可能
  - 作成済みの請求番号を売上詳細に表示
- 二重請求防止
  - 売上行のロックと既存請求の確認により、同じ売上から有効な請求を複数作成しない
- 安全な取消制御
  - 有効な請求データに紐付く売上は、請求を先に取消すまで売上取消不可

## 権限

|操作|admin|staff|
|---|---:|---:|
|掛売会計時の自動請求|○|○|
|現金・カード会計時の任意請求作成|○|—|
|売上履歴からの請求作成|○|—|
|請求の参照|○|○|

スタッフが掛売を確定する場合も、会計処理に組み込まれた請求自動作成のみ許可します。単独での請求作成は管理者に限定しています。

## DB変更

実行対象は [0005_sale_to_invoice.sql](../supabase/migrations/0005_sale_to_invoice.sql) です。

- `invoice_number_sequence`：`INV-000001` 形式の請求番号採番
- `create_invoice_from_sale_internal()`：売上→請求変換の内部トランザクション
- `invoice_from_sale()`：管理者が売上履歴から実行するRPC
- `checkout_sale_with_invoice()`：会計と必要な請求作成を一括実行するRPC
- `cancel_sale()`：有効な請求がある売上の取消を禁止するよう更新

会計と掛売請求は同一のRPCトランザクションで処理されます。請求作成に失敗した場合、売上・明細・支払も保存されません。

## Supabaseでの適用手順

1. Supabase Dashboardの **SQL Editor** を開きます。
2. [0005_sale_to_invoice.sql](../supabase/migrations/0005_sale_to_invoice.sql) の内容をすべて実行します。
3. アプリを再読み込みします。既に開いているレジ画面は更新してください。

## 動作確認

### 掛売

1. レジで顧客と商品を選択します。
2. 支払方法に「掛売」を選択します。
3. 会計を確定します。
4. 完了画面に売上番号・請求番号が出ることを確認します。
5. 売上履歴で該当売上を開き、請求番号が表示されることを確認します。

### 任意の請求作成（管理者）

1. 顧客を選択した現金またはカード会計を確定します。
2. 売上履歴から対象売上を開きます。
3. 件名・請求月・支払期限を確認し、**請求データを作成**を押します。
4. 同じ売上でボタンが消え、請求番号が表示されることを確認します。

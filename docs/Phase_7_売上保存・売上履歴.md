# Phase 7：売上保存・売上履歴

## 今回実装した内容

- レジの「会計を確定」から、売上・売上明細・支払情報を一括で保存
- 会計ごとの UUID を用いた冪等性制御（通信再試行・連打時の二重売上防止）
- 商品、税率、カテゴリ、顧客、車両、支払方法、単価変更権限をサーバー側で再検証
- 現金の預かり金・お釣りをサーバー側で再計算
- 売上番号の自動採番（初期設定では `SAL-000001` 形式）
- 売上履歴の検索・詳細表示
  - 期間、売上番号、顧客、支払方法、担当者
  - 明細、税額、支払内容、顧客、車両を確認
- 管理者のみ売上を論理的に取消可能
- ダッシュボードの「本日の売上」「本日の会計件数」を実データに接続

## DB変更

実行対象は [0004_sales_checkout.sql](../supabase/migrations/0004_sales_checkout.sql) です。

追加される主なDB要素は以下です。

- `sale_number_sequence`
- `round_yen()`：税・数量計算の端数処理
- `checkout_sale()`：会計確定トランザクション
- `cancel_sale()`：売上取消トランザクション
- 売上番号・顧客別履歴の検索インデックス

`checkout_sale()` は、1トランザクションの中で `sales`、`sale_items`、`payments`、`idempotency_requests`、`audit_logs` を更新します。途中で失敗した場合は、売上だけが残ることはありません。

## Supabaseでの適用手順

1. Supabase Dashboard を開く
2. **SQL Editor** で [0004_sales_checkout.sql](../supabase/migrations/0004_sales_checkout.sql) の内容をすべて実行する
3. エラーがないことを確認する
4. アプリを再読み込みし、レジでテスト用の商品を1件会計する

このSQLを適用するまでは、画面の「会計を確定」は正常に完了しません。

## 動作確認

1. 商品マスタで有効な商品・税率・支払方法を用意します。
2. **レジ**で商品を追加し、支払方法を選びます。
3. 現金の場合は、合計以上の預かり金を入力します。
4. **会計を確定**を押し、売上番号と合計が表示されることを確認します。
5. **売上履歴**で該当の売上を選択し、明細・税額・支払方法を確認します。
6. 管理者アカウントであれば、取消理由を入力して取消できます。スタッフには取消ボタンは表示されません。

# Phase 19 帳票車両表示・売上請求完全削除

## 実装前の確認

- レジの「車両（任意）」は、売上の `vehicle_id` として保存されています。
- 帳票では請求の `subject` を「件名」として表示していました。
- 売上・請求の取消は履歴を残す論理的な取消で、物理削除機能はありませんでした。
- 売上・請求の明細、支払、帳票発行履歴には外部キーがあるため、本体だけを直接削除できません。
- 売上・請求テーブルには直接DELETEできるRLSポリシーがありません。

## 実装内容

- 帳票の「件名」を「車両」へ変更しました。
- レジの車両選択肢と帳票は、共通の「ナンバー / 車名」形式を使用します。
- 売上由来の請求書等は、元売上で選択した車両を表示します。
- 手動請求や車両未選択の売上は、帳票の車両欄を空欄で出力します。
- 請求管理と売上履歴に、管理者だけが見える「完全削除」操作を追加しました。
- 完全削除前には、元に戻せないことと削除対象を確認ダイアログで表示します。
- スタッフには完全削除権限もボタンもありません。

## DB変更

`supabase/migrations/0012_document_vehicle_and_permanent_delete.sql` を追加しました。

- `delete_invoice_permanently(uuid)`
  - 管理者権限をDB側で確認します。
  - 請求を元にした帳票発行履歴、請求明細、請求本体を同一トランザクションで削除します。
  - 完全削除の実行記録は監査ログへ残します。
- `delete_sale_permanently(uuid)`
  - 管理者権限をDB側で確認します。
  - 売上を元にした帳票発行履歴、支払、売上明細、売上本体を同一トランザクションで削除します。
  - 紐づく請求がある場合は連鎖削除せず、先に請求を完全削除するようエラーを返します。
  - 完全削除の実行記録は監査ログへ残します。

テーブルへのDELETEポリシーは追加せず、管理者判定を持つ専用RPCだけを削除経路にしています。

## 注意点

- 完全削除したデータは復元できません。通常は「取消」を利用し、誤登録など履歴からも除外する必要がある場合だけ使用してください。
- 自動作成された請求がある売上を完全削除する場合は、請求管理で対象請求を完全削除してから売上を完全削除します。
- 完全削除しても、誰が削除したかを確認できる監査ログは保持します。

## 動作確認方法

1. Supabase SQL Editorで `0012_document_vehicle_and_permanent_delete.sql` を実行します。
2. レジで車両を選択して会計し、自動作成された請求から帳票をプレビューします。
3. 帳票に「車両：ナンバー / 車名」が表示されることを確認します。
4. 車両未選択の会計と手動請求では、車両欄が空欄になることを確認します。
5. スタッフでログインし、売上・請求の完全削除ボタンが表示されないことを確認します。
6. 管理者で請求を完全削除し、一覧から消えることを確認します。
7. 請求が紐づく売上の完全削除が拒否されることを確認します。
8. 請求を先に完全削除した後、売上を完全削除できることを確認します。
